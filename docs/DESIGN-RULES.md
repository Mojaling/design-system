# 디자인 규칙

디자인 규칙은 대부분 **lint가 강제**합니다(`npm run lint`). 에러 메시지가 무엇을 대신 쓸지 알려주니 그대로 따르면 됩니다.
이 문서에는 **lint가 잡지 못하는 것**만 적습니다.

## 1. 화면은 디자인 시스템으로 조립한다

- 버튼·입력·카드·뱃지·수치·바 등은 `@workspace/ui/components/*`를 쓴다.
- 앱 전용 컴포넌트(예: 포지션 카드)는 `apps/<앱>/web/src/components/`에 두고, 디자인 시스템 컴포넌트를 **조합**해서 만든다.
- 기존 컴포넌트를 복사해서 앱 안에 비슷한 버전을 새로 만들지 않는다. 필요한 모양이 없으면 아래 3번을 따른다.

## 2. 레퍼런스는 번역한다

스크린샷이나 다른 사이트를 참고할 때, 그 색·간격·radius를 그대로 옮기지 않는다.
가장 가까운 토큰(`packages/ui/src/styles/globals.css`)과 컴포넌트 variant로 바꿔서 만든다.

## 3. 틀을 바꿀 때는 보고한다

아래는 lint를 통과하지만 **디자인 결정**이다. 했다면 작업 끝에 무엇을, 왜 바꿨는지 사용자에게 보고한다.

- `packages/ui/src/styles/globals.css`에 토큰 추가·변경
- `packages/ui/src/components/*`에 variant·size·컴포넌트 추가·변경
- CSS에 `@utility` 등 새 클래스 추가

## 4. 금지된 우회

- `eslint-disable` 주석: 설정상 무시되고 경고가 난다(`npm run lint`는 경고도 실패로 본다).
- lint 설정(`design-system.lint.json`, `eslint.config.mjs`)을 바꾸는 것: 사람의 승인이 필요하다. 셸 명령으로 우회해서 고치지 않는다.
- `style={{ ... }}`로 색·간격을 넣는 것. 동적인 값(바 너비 등)은 CSS 변수로만 넘긴다(`w-(--x)` + `style={{ "--x": ... }}`).
- 클래스 이름을 문자열로 조립하는 것(`` `bg-${color}` ``). variant를 쓴다.
